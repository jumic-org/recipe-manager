# Domain-split of monolithic Lambda into four handlers (v2)

The 1538-line monolithic handler was decomposed into four domain-specific Lambda functions (recipes, ingredients-on-hand, supermarkets, sort-ingredients) with shared utilities in a `shared/` module. The CDK stack deploys four `NodejsFunction` constructs with route-level API Gateway integrations and scoped IAM permissions. All three issues from the v1 review have been addressed: DynamoDB permissions removed from sort-ingredients, handlers use direct file imports to avoid unnecessary SDK initialization, and the duplicated AI response-parsing logic was extracted into `parseAndMatchGroups`.

**Watch for:** The recipes handler still imports via the barrel (`from '../shared'`), which is intentional since it uses every export — but if a new shared module is added later, recipes will pick it up silently [confirmed, low-risk].

**Verdict**: APPROVED

## High-level view

The v1 concerns are resolved. The sort-ingredients Lambda no longer receives DynamoDB grants or `TABLE_NAME`, bringing it in line with least-privilege. The three handlers that don't need all SDK clients (ingredients-on-hand, supermarkets, sort-ingredients) now import directly from the specific shared files they need, so cold starts only initialize the clients each handler actually calls. The recipes handler retains the barrel import because it genuinely uses every export.

The `parseAndMatchGroups` helper consolidates the duplicated response-parsing logic in sort-ingredients, handling markdown fence stripping, JSON parsing, format normalization, and fuzzy ingredient matching in one place.

## Barrel coupling in recipes handler

```typescript
import { docClient, TABLE_NAME, bedrockClient, response, getUserId } from '../shared';
```

This pulls in all four shared modules. Today this is functionally correct since recipes uses everything. The risk is forward-looking: any new export added to the barrel will be initialized on cold start whether recipes uses it or not. The other three handlers demonstrate the direct-import pattern, so switching recipes would be a one-line change per import.
